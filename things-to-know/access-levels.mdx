title: Access levels
description: Distinguish Engine membership, thread permissions, and contract roles.
---

| Setting | Controls |
| --- | --- |
| Engine role (`admin`, `member`, `viewer`) | Dashboard and management access |
| Thread access level | Operations and notifications within a thread |
| Contract role, such as `processor` | Which party may report a contract step |

## Thread permissions

The current bundled runtime permissions are:

| Access level | Operations | Notifications |
| --- | --- | --- |
| Owner | Read, write, invite, end | All |
| Participant | Read, write, end | Own step outcomes and validation results |
| Observer | Read and write | Critical, timeout, and retry-limit violations |
| External | Read own data; write | Own step outcomes |

**Observer currently includes write permission.** Do not treat that name as a
read-only guarantee. See the [bundled role definitions](https://github.com/ThreadifyDev/engine/blob/main/threadify-go/shared/rbac/roles.json).

Choose `accessLevel` when [inviting a party](/core-concepts/thread-collaboration/inviting-parties).
Its `role` separately identifies the contract party. Direct joins use participant
access; invitation joins use the granted access level.

For Engine users and API keys, see [authentication](/authentication).
