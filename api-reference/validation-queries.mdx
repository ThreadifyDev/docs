## A thread's results

```graphql
query {
  thread(id: "THREAD_ID") {
    validationResults(options: { limit: 20 }) {
      stepName
      overallStatus
      hasCriticalViolation
      validations {
        type
        message
        field
        expected
        actual
      }
    }
  }
}
```

`options` accepts `stepName`, `stepId`, `idempotencyKey`, `validationType`,
`limit` (maximum 100) and `offset`.

To fetch one step's results directly, use
`validationResults(threadId, stepName, idempotencyKey)`; all three are required.

| Field | Meaning |
| --- | --- |
| `validationId` | Result ID |
| `stepId`, `stepName`, `idempotencyKey` | The step that was checked |
| `timestamp` | When it was checked |
| `overallStatus` | Overall result |
| `hasCriticalViolation` | Whether any finding is critical |
| `criticalCount`, `warningCount`, `minorCount`, `infoCount`, `totalValidations` | Counts |
| `validations` | Findings: `type`, `message`, `field`, `expected`, `actual`, `rule` |

The finding types are listed under
[Validation results](/core-concepts/data-retrieval/validation-results#finding-types).

## Violations across threads

```graphql
query {
  contractViolations(contractName: "refund_review", severity: ["critical", "major"], limit: 50) {
    threadId
    stepName
    violationType
    severity
    message
    timestamp
  }
}
```

Filter by `contractName`, by reference (`refKey` and `refValue`), by `severity`,
and by `startedAfter` / `startedBefore`. Default limit 50.

## Notification counts

For a quick overview of a thread before loading everything:

```graphql
query {
  thread(id: "THREAD_ID") {
    notificationSummary {
      totalNotifications
      criticalCount
      majorCount
      warningCount
      hasCritical
    }
  }
}
```

`notifications(options)` on a thread returns the notifications themselves, with
the same fields as `contractViolations`.
