### Creating or Resuming a Thread

A thread is one workflow execution, such as an order, support ticket or customer
onboarding. Its steps form an execution graph across every participating service.
Use the application's durable process key to recover the same thread in later
requests. A new key creates a thread; a closed key rejects further writes.
See [resume across requests](/core-concepts/threads#resume-across-requests).

<CodeGroup>

```javascript JavaScript
const thread = await threadify.thread('User-Onboarding-cust-123', { label: 'User-Onboarding-cust-123' });
```

```go Go
thread, err := conn.Thread(ctx, "User-Onboarding-cust-123", threadify.ThreadOptions{Label: "User-Onboarding-cust-123"})
if err != nil {
    log.Fatal(err)
}
```

```python Python
thread = await connection.thread("User-Onboarding-cust-123", {"label": "User-Onboarding-cust-123"})
```

</CodeGroup>

### Recording Steps

Always create the step **before** executing business logic:

<CodeGroup>

```javascript JavaScript
const step = thread.step('order_received');

// Execute business logic
const order = await receiveOrder();

// Record success with context
await step.addContext({ orderId: order.id, total: order.total }).success();
```

```go Go
step := thread.Step("order_received")

// Execute business logic
order, err := receiveOrder()
if err != nil {
    log.Fatal(err)
}

// Record success with context
_, err = step.AddContext(map[string]any{"orderId": order.ID, "total": order.Total}).Success(ctx)
if err != nil {
    log.Fatal(err)
}
```

```python Python
step = thread.step("order_received")

# Execute business logic
order = await receive_order()

# Record success with context
await step.add_context({"orderId": order.id, "total": order.total}).success()
```

</CodeGroup>

### Step Methods

| Method | Description |
|--------|-------------|
| `.success()` | Mark step as successful |
| `.success(message)` | Record success with a message or metadata |
| `.failed(message)` | Record a failed outcome |
| `.addContext(data)` | Add business context (analytics, debugging) |

<Warning>
Non-contract threads remain "active" indefinitely unless explicitly ended. [View Closing a Thread](/core-concepts/ending-threads)
</Warning>

An acknowledgement means the event was recorded, not that asynchronous contract
validation has passed. Use `.success(message, { waitFor: true })` for the exact
validation result, or call `thread.waitFor(stepName)` before the business operation.
See [execution waits](/core-concepts/execution-waits).

### Idempotency

Threadify stores only the first recording for an idempotency key. See
[Idempotency](/core-concepts/idempotency) when retries need a custom key.
