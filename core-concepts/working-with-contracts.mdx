---
title: Use a contract
description: Start a thread on a contract version and check each step as you report it.
---

These examples use the `refund_review` contract from
[Write a contract](/core-concepts/creating-contracts). Publish it first. The
connection reports as the `processor` role, which the contract makes the owner
of both steps.

<CodeGroup>
```javascript JavaScript
const thread = await connection.thread('refund:RF-123', {
  label: 'Refund RF-123',
  contract: 'refund_review',
  role: 'processor',
});

await thread.step('approval')
  .addContext({ reference: 'PAY-123' })
  .success('Approved', { waitFor: true });

await thread.step('refund')
  .addContext({ reference: 'PAY-123', amount: 42, currency: 'GBP', receipt: 'RF-12345678' })
  .success('Refund recorded', { waitFor: true });
```
```go Go
thread, err := conn.Thread(ctx, "refund:RF-123", threadify.ThreadOptions{
    Label:    "Refund RF-123",
    Contract: "refund_review",
    Role:     "processor",
})
if err != nil {
    return err
}

_, err = thread.Step("approval").
    AddContext(map[string]any{"reference": "PAY-123"}).
    Success(ctx, "Approved", threadify.ReportOptions{WaitFor: true})
if err != nil {
    return err
}

_, err = thread.Step("refund").
    AddContext(map[string]any{"reference": "PAY-123", "amount": 42, "currency": "GBP", "receipt": "RF-12345678"}).
    Success(ctx, "Refund recorded", threadify.ReportOptions{WaitFor: true})
if err != nil {
    return err
}
```
```python Python
thread = await connection.thread("refund:RF-123", {
    "label": "Refund RF-123",
    "contract": "refund_review",
    "role": "processor",
})

await thread.step("approval").add_context({"reference": "PAY-123"}).success(
    "Approved", wait_for=True,
)

await thread.step("refund").add_context({
    "reference": "PAY-123", "amount": 42, "currency": "GBP", "receipt": "RF-12345678",
}).success("Refund recorded", wait_for=True)
```
</CodeGroup>

Because `refund` is the terminal step, the thread completes when it passes.

`waitFor: true` makes each call wait until Threadify has checked the step, and
fails if the step broke the contract. Without it, the call returns as soon as
the step is recorded. See
[Recording is not the same as passing](/core-concepts/overview#recording-is-not-the-same-as-passing).

This example records a refund after it happened. To stop a refund the contract
doesn't allow yet, [ask for permission first](/core-concepts/execution-waits).

## Choose a version

`refund_review` uses the latest published version when the thread is created.
Use `refund_review:2` to choose one. A thread keeps its version for its whole
life, even after you publish a newer one.

When you resume the thread later, leave `contract` out. The stored version is
used automatically. Passing a different contract or version is rejected.

## When a step breaks the contract

- With `waitFor: true`, the call fails with the violation attached.
- Otherwise the step is recorded and marked as violated. Find it in the
  dashboard, through [validation results](/core-concepts/data-retrieval/validation-results),
  or by [subscribing](/core-concepts/notifications/subscribing) to `rule.violated`.

Threadify won't stop your code from continuing. If the next action matters,
check the result before you take it.
