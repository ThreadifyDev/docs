---
title: Use a contract
description: Attach a versioned contract to a thread and record its steps.
---

[Create `refund_review`](/core-concepts/creating-contracts) before running these
examples. Connect the SDK to your Engine with an API key and report as the
contract's `processor` role.

<CodeGroup>
```javascript JavaScript
const thread = await connection.thread('refund:RF-123', { label: 'Refund RF-123', contract: 'refund_review', serviceName: 'processor' });
await thread.step('approval').addContext({ reference: 'RF-123' })
  .success('Approved', { waitFor: true });
await thread.step('refund').addContext({
  reference: 'RF-123', amount: 42, currency: 'GBP', receipt: 'RF-12345678'
}).success('Refund recorded', { waitFor: true });
```
```go Go
thread, err := conn.Thread(ctx, "refund:RF-123", threadify.ThreadOptions{Label: "Refund RF-123", Contract: "refund_review", Role: "processor"})
if err != nil { return err }
_, err = thread.Step("approval").AddContext(map[string]any{"reference": "RF-123"}).
    Success(ctx, "Approved", threadify.ReportOptions{WaitFor: true})
if err != nil { return err }
_, err = thread.Step("refund").AddContext(map[string]any{
    "reference": "RF-123", "amount": 42, "currency": "GBP", "receipt": "RF-12345678",
}).Success(ctx, "Refund recorded", threadify.ReportOptions{WaitFor: true})
if err != nil { return err }
```
```python Python
thread = await connection.thread("refund:RF-123", {"contract": "refund_review", "role": "processor", "label": "Refund RF-123"})
await thread.step("approval").add_context({"reference": "RF-123"}).success(
    "Approved", wait_for=True,
)
await thread.step("refund").add_context({
    "reference": "RF-123", "amount": 42, "currency": "GBP", "receipt": "RF-12345678",
}).success("Refund recorded", wait_for=True)
```
</CodeGroup>

These examples record outcomes; they do not execute a real refund. To prevent
an operation before it happens, obtain a [permission grant](/core-concepts/execution-waits)
and execute only after it succeeds.

## Versions

Pass `refund_review:2` to choose a specific version. Omitting the version selects
the latest when the thread is created; publishing a later version does not
rewrite an existing thread's contract. Later requests use only the same thread
key to resume; omit `contract` to load the stored binding and pinned version.
Supplying a different contract or version is rejected. See the
[cross-language resume examples](/core-concepts/threads#resume-across-requests).

## Interpret results

- A normal recording acknowledgement is not a completed validation decision.
- `{ waitFor: true }` waits for that particular reported event's validation.
- A failed operation can satisfy its contract; operation outcome and rule
  compliance are separate facts.
- A successfully validated terminal step completes the thread.

Subscribe to [notifications](/core-concepts/notifications/subscribing) or inspect
[validation results](/core-concepts/data-retrieval/validation-results) to investigate
violations. Recording telemetry does not automatically stop the caller's code.
