---
title: Record failures
description: Report steps that failed or errored, and record retries.
---

Report a failure as a step outcome rather than skipping the step. That way the
dashboard, your contract and your entity profile metrics all see it.

<CodeGroup>
```javascript JavaScript
const step = thread.step('payment_processed');

try {
  const payment = await processPayment(orderId);
  await step.addContext({ paymentId: payment.id }).success();
} catch (error) {
  await step.failed({ message: error.message, errorCode: 'PAYMENT_FAILED' });
}
```
```go Go
step := thread.Step("payment_processed")

payment, err := processPayment(orderID)
if err != nil {
    _, reportErr := step.Failed(ctx, map[string]any{
        "message":   err.Error(),
        "errorCode": "PAYMENT_FAILED",
    })
    return errors.Join(err, reportErr)
}

_, err = step.AddContext(map[string]any{"paymentId": payment.ID}).Success(ctx)
return err
```
```python Python
step = thread.step("payment_processed")

try:
    payment = await process_payment(order_id)
    await step.add_context({"paymentId": payment.id}).success()
except Exception as error:
    await step.failed({"message": str(error), "errorCode": "PAYMENT_FAILED"})
```
</CodeGroup>

Use `failed` when the operation ran and didn't succeed, such as a declined card.
Use `error` when something went wrong unexpectedly, such as an exception or a
timeout. Both accept a message string or an object of details.

## Retries

Each attempt is its own report:

- If you use [`waitFor`](/core-concepts/execution-waits), each grant covers one
  attempt, so request a new grant before retrying.
- Otherwise, give each attempt its own
  [idempotency key](/core-concepts/idempotency), such as `payment:ORD-1:attempt-2`.
  Reusing the same key makes the retry look like a duplicate.

If your contract uses `must succeed before each invocation`, a retry needs a new
approval, even after a failed attempt.

A failure isn't automatically a contract violation, and a contract can allow
retries. See
[Recording is not the same as passing](/core-concepts/overview#recording-is-not-the-same-as-passing).
