---
title: Finish a thread
description: Complete or cancel threads that don't have a contract.
---

A thread with a contract completes by itself when its terminal step passes.
A thread without a contract stays active until you finish it.

<CodeGroup>
```javascript JavaScript
const thread = await connection.thread('order:ORD-123', { label: 'Order ORD-123' });

await thread.step('process_order').success();
await thread.step('send_email').success();

await thread.complete('All steps finished');
// or, if the run was abandoned:
await thread.cancel('Customer cancelled the order');
```
```go Go
thread, err := conn.Thread(ctx, "order:ORD-123", threadify.ThreadOptions{Label: "Order ORD-123"})
if err != nil {
    return err
}

// ... record steps ...

if _, err := thread.Complete(ctx, "All steps finished"); err != nil {
    return err
}
// or: thread.Cancel(ctx, "Customer cancelled the order")
```
```python Python
thread = await connection.thread("order:ORD-123", {"label": "Order ORD-123"})

# ... record steps ...

await thread.complete("All steps finished")
# or, to cancel:
await thread.close("Customer cancelled the order")
```
</CodeGroup>

| | Complete | Cancel |
| --- | --- | --- |
| JavaScript | `thread.complete(reason?)` | `thread.cancel(reason?)` |
| Go | `thread.Complete(ctx, reason...)` | `thread.Cancel(ctx, reason...)` |
| Python | `thread.complete(reason?)` | `thread.close(reason?)` |

A thread with a contract can't be completed by hand before it reaches a
terminal step.

Once a thread is completed or cancelled, it can't be reopened or receive more
steps, and its key stays attached to it. Use a new key for the next run.

## Notifications

Finishing a thread sends a notification you can
[subscribe to](/core-concepts/notifications/subscribing):

- `thread.completed`: the thread was completed by hand or reached its terminal step.
- `thread.cancelled`: the thread was cancelled.
