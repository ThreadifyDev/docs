---
title: Subscribe to events
description: React in your code when steps succeed or fail, rules are broken, or threads finish.
---

Subscribe on a connection to get notified about threads your service takes
part in. Each notification must be [acknowledged](/core-concepts/notifications/handling).

<CodeGroup>
```javascript JavaScript
// Thread events: event and handler
connection.subscribe('thread.completed', (notification) => {
  console.log('Thread completed', notification.threadId);
  notification.ack();
});

// Step events: event, step name and handler
connection.subscribe('step.failed', 'payment_processed', (notification) => {
  console.error('Payment failed:', notification.message);
  notification.ack();
});

// Only for one contract: contract@step
connection.subscribe('rule.violated', 'refund_review@refund', (notification) => {
  console.error('Rule broken:', notification.message);
  notification.ack();
});
```
```go Go
// Thread events: pass "" as the step name
err := conn.Subscribe(ctx, "thread.completed", "", func(n *threadify.Notification) {
    fmt.Println("Thread completed", n.ThreadID)
    n.Ack()
})

// Step events
err = conn.Subscribe(ctx, "step.failed", "payment_processed", func(n *threadify.Notification) {
    fmt.Println("Payment failed:", n.Message)
    n.Ack()
})

// Only for one contract: contract@step
err = conn.Subscribe(ctx, "rule.violated", "refund_review@refund", func(n *threadify.Notification) {
    fmt.Println("Rule broken:", n.Message)
    n.Ack()
})
```
```python Python
def on_completed(notification):
    print("Thread completed", notification.thread_id)
    notification.ack()

def on_payment_failed(notification):
    print("Payment failed:", notification.message)
    notification.ack()

def on_rule_broken(notification):
    print("Rule broken:", notification.message)
    notification.ack()

# Thread events: event and handler
connection.subscribe("thread.completed", on_completed)
# Step events: event, step name and handler
connection.subscribe("step.failed", "payment_processed", on_payment_failed)
# Only for one contract: contract@step
connection.subscribe("rule.violated", "refund_review@refund", on_rule_broken)
```
</CodeGroup>

## Events

| Event | When |
| --- | --- |
| `thread.completed` | A thread was completed |
| `thread.cancelled` | A thread was cancelled |
| `step.success` | A step succeeded |
| `step.failed` | A step failed |
| `rule.passed` | A step passed its contract check |
| `rule.violated` | A step broke its contract |
| `step.*`, `rule.*` | Any step event, or any contract check |

Which notifications you receive also depends on your
[access level](/things-to-know/access-levels#thread-access-levels) on each thread.

## Notification fields

| Field | Meaning |
| --- | --- |
| `notificationId` | Unique ID. Use it to ignore repeats. |
| `threadId`, `stepName` | Where it happened |
| `stepStatus` | `success`, `failed` or `error` |
| `status` | `passed` or `violated`, for `rule.*` events |
| `severity` | `critical`, `major`, `minor`, `warning` or `info` |
| `message` | A readable description |
| `timestamp` | When it happened |
| `ack()` | Acknowledge it |

In Python the fields use snake case (`thread_id`, `step_name`). In Go they're
struct fields (`ThreadID`, `StepName`).

## How many at once

By default, up to 10 notifications can be waiting for your acknowledgement. When
that many are outstanding, the Engine waits before sending more. Raise it with
`maxInFlight` (up to 100) when you [connect](/core-concepts/connecting#options).
