### Acknowledging

**You must call `notification.ack()`** to confirm processing:

<CodeGroup>

```javascript JavaScript
threadify.on('rule.violated', 'order_placed', async (notification) => {
  try {
    await processViolation(notification);
    notification.ack();  // ACK on success
  } catch (error) {
    // Don't ACK on failure; allow configured redelivery
  }
});
```

```go Go
err := conn.Subscribe(ctx, "rule.violated", "order_placed", func(n *threadify.Notification) {
    err := processViolation(n)
    if err != nil {
        // Don't ACK on failure; allow configured redelivery
        return
    }
    n.Ack() // ACK on success
})
if err != nil {
    log.Fatal(err)
}
```

```python Python
def on_violation(notification):
    try:
        process_violation(notification)
        notification.ack()  # ACK on success
    except Exception:
        # Don't ACK on failure; allow configured redelivery
        pass

connection.subscribe("rule.violated", "order_placed", on_violation)
```

</CodeGroup>

### Retry behavior

The Engine's NATS consumer configuration controls the acknowledgement timeout and
maximum delivery attempts. An acknowledgement can be lost after your handler has
already completed, so the same notification can arrive again.

Use the notification ID to deduplicate completed work, and use the destination
service's idempotency mechanism when triggering an external action. Acknowledge
after successful processing. Log failed handling attempts so you can investigate
when the configured delivery limit is reached.
