---
title: Acknowledge notifications
description: Acknowledge each notification after you've handled it, and handle repeats safely.
---

Call `ack()` once you've finished handling a notification. If you don't, the
Engine sends it again.

<CodeGroup>
```javascript JavaScript
connection.subscribe('rule.violated', 'refund', async (notification) => {
  try {
    await openIncident(notification);
    notification.ack();
  } catch (error) {
    // No ack: it will be delivered again.
  }
});
```
```go Go
err := conn.Subscribe(ctx, "rule.violated", "refund", func(n *threadify.Notification) {
    if err := openIncident(n); err != nil {
        return // No ack: it will be delivered again.
    }
    n.Ack()
})
```
```python Python
def on_violation(notification):
    try:
        open_incident(notification)
        notification.ack()
    except Exception:
        pass  # No ack: it will be delivered again.

connection.subscribe("rule.violated", "refund", on_violation)
```
</CodeGroup>

## Redelivery

A notification that isn't acknowledged within 30 seconds is sent again, up to
three times in total. After that it's dropped, so log failures you need to
follow up on.

You can receive the same notification more than once even when your handler
succeeded, for example if the acknowledgement was lost on the way back. So:

- Use `notificationId` to skip notifications you've already handled.
- If the handler triggers something external, such as a payment or an email,
  use that system's own idempotency key too.
