Connect an MCP client using these settings:

| Setting | Value |
| --- | --- |
| Transport | **Streamable HTTP**, despite the `/sse` path |
| URL | `https://threadify.example.com/sse` |
| Header | `X-API-Key: YOUR_ENGINE_API_KEY` |

Use your Engine address, available under **Settings → Engine**. Its embedded
MCP endpoint needs no separate server package.

## Tools

| Tool | Purpose |
| --- | --- |
| `get_thread` | Inspect a thread and its recorded execution |
| `search_threads` | Find threads by contract, actor, status, dates, or tags |
| `get_entity_profile` | Read an entity's profile, metrics, and health |
| `get_contract_violations` | Find recorded rule violations |
| `query` | Run a GraphQL query for more specific evidence |

The `graphql://schema` resource exposes the schema. Built-in prompts include
`investigate_thread`, `analyse_entity_delivery`, and `identify_delivery_failures`.
Discover tool input schemas through your MCP client.

## What an assistant can tell you

Ask what failed, which approval preceded an action, or which problems recur.
Answers depend on recorded history and the key's permissions. For empty results,
check filters and telemetry ingestion.

MCP investigation does not enforce tool execution. Use
[execution waits](/core-concepts/execution-waits) in the tool handler when a
contract must gate the action itself.
