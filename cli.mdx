`threadify-cli` manages your Engine from a terminal or a CI job. It reads and
changes resources. To record steps, use an [SDK](/quickstart) or
[OpenTelemetry](/opentelemetry).

## Install

Download a release for your platform from
[GitHub](https://github.com/ThreadifyDev/cli/releases), check its checksum, and
put `threadify-cli` on your `PATH`. It's installed separately from the Engine.

## Sign in

```sh
threadify-cli login --api-url https://threadify.example.com
threadify-cli whoami
```

`login` opens your browser. Sign in to the dashboard and choose
**Approve CLI login**. On a remote machine, add `--no-browser` to print the
approval link instead.

- The approval link is valid for five minutes.
- The CLI login lasts 30 days. Changing your role, suspending you, or revoking
  the key the login came from ends it sooner.
- `threadify-cli logout` revokes the login. It doesn't revoke API keys you
  configured yourself.

Browser login needs the Engine's
[`server.browser_origin`](/self-hosting#put-it-behind-https) to be set correctly.

## Use an API key (CI and scripts)

```sh
threadify-cli config set api-url https://threadify.example.com
export THREADIFY_API_KEY='your-service-account-key'
threadify-cli contracts list
```

To save a key in the CLI config without putting it on the command line, pipe it in:

```sh
printf '%s' "$THREADIFY_API_KEY" | threadify-cli config set --api-key-stdin
```

`threadify-cli config show` prints the config with the key hidden. Prompts are
off when `--no-input` is passed or `CI=true` is set.

### Where settings come from

| Setting | Order (first wins) |
| --- | --- |
| Engine URL | `--api-url`, `THREADIFY_API_URL`, `THREADIFY_ENGINE_URL`, saved config |
| API key | `--key`, saved login or key for that Engine, `THREADIFY_API_KEY` |
| Config file | `THREADIFY_CLI_CONFIG`, otherwise `~/.config/threadify/cli.yaml` |

Changing the saved Engine URL clears the saved credential.

### Output

Commands print JSON to stdout and errors to stderr, and exit non-zero on
failure. The default timeout is 30 seconds; change it with `--timeout 1m`. Use
`--file -` to read input from stdin.

Writes aren't retried automatically. If a write times out, check whether it
happened before you run it again.

## Contracts

```sh
threadify-cli contracts preview --file refund.feature
threadify-cli contracts create --file refund.feature
threadify-cli contracts list --search refund --limit 25
threadify-cli contracts get --id CONTRACT_ID [--version 1]
threadify-cli contracts update --id CONTRACT_ID --file refund.feature
threadify-cli contracts versions --id CONTRACT_ID
threadify-cli contracts delete --id CONTRACT_ID --yes
```

`update` publishes a new version. See [Write a contract](/core-concepts/creating-contracts).

## Entity profiles

```yaml
# customers.yaml
name: Customers
type: [customer_id]
description: Customer workflows
```

```sh
threadify-cli profile-types create --file customers.yaml
threadify-cli profile-types list
threadify-cli profiles create --type-id TYPE_ID --ref-value CUST-001 --name 'Jane Doe'
threadify-cli profiles list --type Customers
threadify-cli profiles get --type Customers --ref-value CUST-001
threadify-cli profiles get --id PROFILE_ID
threadify-cli profiles history --id PROFILE_ID
```

Running `profiles create` again with the same type and reference updates the
name. See [Entity profiles](/core-concepts/entity-profiles).

## Threads

```sh
threadify-cli threads resolve --thread-key order:ORD-1001 --label 'Order ORD-1001' \
  --contract checkout --role worker \
  --refs '{"order_id":"ORD-1001","customer_id":"CUST-001"}' --tags '["checkout"]'
threadify-cli threads get --id THREAD_ID
threadify-cli threads list --status active --limit 25
threadify-cli threads find --ref-key order_id --ref-value ORD-1001
threadify-cli threads add-refs --id THREAD_ID --refs '{"ticket_id":"T-123"}'
threadify-cli threads close --id THREAD_ID --status completed
threadify-cli threads verify --id THREAD_ID
```

- `resolve` creates or resumes a thread by its key, like
  [`connection.thread()`](/core-concepts/threads). `--contract` and `--role` are
  only needed for a new contracted thread.
- `find` returns every thread with that reference.
- `close` needs `--status completed` or `--status cancelled`.
- `verify` checks the thread's [integrity](/things-to-know/hash-chain) and exits
  non-zero if it fails.

## Skills for coding agents

The CLI includes instructions that help coding agents write contracts and
investigate threads. Install them for your agent:

```sh
threadify-cli skills install --agent claude    # or codex, cursor, copilot, all
```

They're installed for your user by default; add `--project` to install them in
the current repository. Skills you've edited are kept unless you pass `--force`.
Installing skills doesn't need an Engine or a key.

Run `threadify-cli help` for the full command list.
