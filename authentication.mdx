title: Authentication

There are three credentials, each with one job:

| Credential | Used for |
| --- | --- |
| Threadify account | Signing up and managing your license |
| License key | Starting your Engine. It goes in `config.yaml` and nowhere else. |
| Engine API key | Everything that talks to your Engine: SDKs, OpenTelemetry, MCP, the CLI and scripts |

Users and API keys belong to your Engine. Your Threadify account doesn't give
anyone access to another company's Engine.

## Sign in

Open your Engine's address in a browser and choose:

- **Continue with email or SSO** to sign in with your Threadify account, or
- **Sign in with API key** to open a session with that key's permissions.

The license owner can sign in straight away. Everyone else needs an invitation:
an admin opens **Team**, chooses a role (`admin`, `member` or `viewer`), and
sends the person the sign-in link Threadify shows. Threadify doesn't email
invitations for you.

Browser sessions last eight hours. Signing out, suspending the user, or revoking
the API key a session was opened with ends it immediately.

## Create an API key

Open **Developer → API Keys**. For an integration, create a service account and
give it only the permissions it needs. Send the key in the `X-API-Key` header
when you call the Engine directly.

To use the CLI, sign in with your browser instead of copying a key:

```bash
threadify-cli login --api-url https://threadify.example.com
```

See the [CLI guide](/cli) for headless servers and CI.

## Browser sign-in behind a proxy

Set `server.browser_origin` to the exact address people open, and
`server.public_url` to the address SDKs should use. These are usually the same:

```yaml
server:
  public_url: "https://threadify.example.com"
  browser_origin: "https://threadify.example.com"
```

See [Put it behind HTTPS](/self-hosting#put-it-behind-https).
